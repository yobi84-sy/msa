# 문제 해결 기록

[프로젝트 홈](../README.md) · [검증 범위](validation.md)

## 모니터링 앱이 Synced여도 마지막 Sync가 실패

**증상** · Argo CD 모니터링 앱에서 Healthy/Synced와 Sync failed 기록이 함께 보였습니다.

**원인** · 큰 Grafana ConfigMap을 client-side apply할 때 last-applied annotation 크기 제한에 걸린 사례입니다. 현재 상태와 마지막 작업 결과는 다른 정보입니다.

**변경** · 모니터링 소유권에서 server-side apply를 사용하고 client-side migration 옵션을 구분했습니다.

**확인** · 당시 Argo 동기화와 Grafana 접속을 확인했습니다. [모니터링 Application](../argocd/apps/msa-monitoring.yml)에서 현재 sync 옵션을 볼 수 있습니다. 이 원인을 모든 Sync 실패의 공통 원인으로 일반화하지 않습니다.

## 설치가 끝났는데 S3가 대기로 남고 전체 실패로 표시

**증상** · 작업 로그는 끝났지만 GUI의 S3 완료 수집이 빠져 전체 결과가 실패처럼 보였습니다.

**원인** · 자원 생성 여부, 앱 준비 상태, 실행 이벤트의 집계가 하나의 진행률에 섞인 문제였습니다.

**변경** · 통합 GUI에서 실제 리소스 상태와 실행 이벤트를 나누고, 상품 이미지 객체·카탈로그 검증과 완료 표시를 보완했습니다.

**확인** · 로컬 이벤트 재생/완료 표시 검사와 실습 상품 이미지 표시를 구분해 확인했습니다. GUI 보완은 별도 통합 실행 패키지에 있습니다.

## 패치 JSON 처리 오류 뒤 GUI 응답 지연

**증상** · GitHub compare 응답을 읽는 중 JSON 오류가 발생했고 긴 오류 본문이 화면에 표시되면서 GUI가 느려졌습니다.

**변경** · native 출력 인코딩과 오류 캡처, GUI 표시 로그 길이·줄 수를 보완했습니다. 전체 원문은 로그 파일에서 확인하고 화면 표시량은 제한합니다. Windows PowerShell에서 필요한 함수/모듈 범위도 점검했습니다.

**확인** · 큰 오류 문자열을 넣는 로컬 검사와 패치 실행 인계 검사를 수행했습니다. 통합본 보완이며 원격의 모든 예전 GUI/스크립트가 같은 버전이라는 뜻은 아닙니다.

## 메일 확인 전 패치가 중단됨

**증상** · order-email 구독 확인을 먼저 완료하라는 오류로 패치가 중단됐습니다.

**원인** · SNS 구독 생성과 수신자의 확인은 별도 단계였습니다. 장애 토픽 확인이 주문 토픽까지 확인한 것은 아닙니다.

**조치·확인** · 새 주문용 확인 메일에서 구독을 승인한 뒤 진행했습니다. 이후 신규 주문 이메일 수신을 확인했습니다. [알림 흐름](observability.md)을 참고합니다.

## 기본 접속은 되는데 품절 공개 설정 저장만 실패

**증상** · 일반 페이지와 재고 보충은 정상이나 관리자 설정 저장은 실패했습니다.

**원인** · 3차 패치에서 의도한 프런트/API 경로 계약 불일치였습니다.

**조치·확인** · 4차 복구 패치 후 같은 설정을 저장하고 새로고침해 값 유지를 확인했습니다. [장애 빌드](https://github.com/yobi84-sy/msa/actions/runs/39137464044)와 [복구 빌드](https://github.com/yobi84-sy/msa/actions/runs/39138395458)는 모두 CI가 성공할 수 있습니다. CI 성공이 기능 장애 부재를 의미하지 않는 사례입니다.

## 삭제 계획과 write-only DB 비밀번호 버전

**증상** · 삭제 중 Terraform exit 1로 중단된 기록이 있었습니다. 마지막 exit 메시지만으로 원인을 판단하지 않고 앞선 Terraform 오류를 확인했습니다.

**보완** · 통합 실행 패키지에서 삭제 전용 계획에 DB 비밀번호 갱신 버전을 전달하지 않도록 조건을 추가하고 DNS/NLB 정리·백업 절차를 유지했습니다.

**확인** · 이후 실제 삭제 완료와 관리 state·대상 VPC 부재를 확인한 기록이 있습니다. 공개 저장소의 이전 삭제 스크립트와 통합본의 최신 삭제 보완은 구분해서 사용합니다. [실행 안내](runbook.md)를 먼저 확인합니다.
